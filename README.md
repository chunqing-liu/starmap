# 星图流程看板

星图是 Portal Desktop 的流程协作插件。插件 ID 保持 community.pipeline，更新不清空已有本机数据。

团队源码、版本更新与正式发布以公司 GitLab 的 `agent-team/starmap` 项目为唯一依据；协作分支、MR 和分发规则见 `CONTRIBUTING.md`。

## 1.5.2 新功能

- 默认流程分成两段：开发闭环从需求确认走到交付核验，做完就是开发完成，不用再等正式测试和最终验收；上线准出单独一条线，只管能不能上线。
- 新建流程默认用这套双轨模板；想要别的走法可以在看板上自由编辑，改过的模板不会覆盖已经发出去的历史。
- 开发轨有必做的「开发自测」：先用可执行契约在工作台跑真实路径，自测不过不进实现审核。实现审核通过时会锁定一个固定候选（版本、环境、租约），正式测试只认这个候选，同版本的有效证据可以直接复用。
- 测试设计是独立一步，H2 退回会回到写测试设计的人手上，不吃开发迭代；正式测试发现实现缺陷只复测受影响项，原来的快照和失败证据保留。
- H1/H4 仍然人工拍板；H2 测试设计审核、H3 实现审核默认由独立 Agent 自动判定，命中语义例外、覆盖不可判定或范围扩大时才转人工。
- 每条需求和流程会记下按哪版规范运行，规范升级后旧的需求仍按当时的规范核对。
## 1.5.0 新功能

- GitLab 团队数据读写通过宿主公开 grove.network.fetch 接口，不依赖被 CSP 阻止的原生请求。
- 编辑短暂合并后自动上传；前台默认每 5 秒检查远端版本，可选择 3–60 秒。激活、重连立即检查，失败退避。这是秒级更新，不是即时推送。
- 安全可合并的不同字段自动合并；双方修改同一字段时明确选择，不静默覆盖；提交仍检查文件版本。
- 网络中断保留本机草稿；写入回执不明先拉取核对，不盲目重发。账号、仓库、分支和空间的草稿隔离。
- 真实操作发生后记录节点进出时间、阶段耗时，显示并行当前节点。旧历史没有记录时显示“未记录”，不推算伪造时间。
- 手动催办检查当前节点、并行负责人及地址，展示每位负责人的模拟结果并防重复。**本版仅模拟发送，不向任何人发消息。**
- 同组 Being 可创建星轨、节点和编辑自定义流程。闸口保护删除，不额外增加指定负责人硬审批。

## 兼容与安装

使用 **Portal Desktop 0.1.10 或更新的兼容版本**（公开 SDK 至少 1.5.0）。已实测 0.1.10；更高版本需继续保持 API 1 / SDK 1.5 兼容，不能视为已逐版测试。0.1.9 不在本次正式支持范围。

从公司 GitLab 项目的 Release 获取 desktop-plugin.tar.gz，在桌面插件管理中通过受支持的本地导入方式加载；也可待 Grove 条目更新后从 Grove 更新。本仓库发布不自动更新 Grove。不要把压缩包解压后替换运行中的生产数据目录。

## 首次联网

1. 打开星图，点击轻量入口“登录 / 联网设置”。面板默认按团队「Lite 项目组」设好，不用手动填服务器、项目、分支。
2. 面板已预设团队「Lite 项目组」：公司 GitLab、项目 724、分支 lite、空间 lite。只需在访问令牌框输入自己的令牌，点“连接”。不要把令牌放入 URL、聊天或配置文件。
3. 插件只读核验账号、项目和分支，成功后收起设置。缺分支、403 或 404 不创建、不重置、不换仓，也不回退 master。要连别的团队时展开“高级设置”填写入口、项目、分支和空间，或粘贴对方给的连接信息。
4. 已有空间会拉取数据；新空间第一次写入需明确确认，随后编辑自动同步。旧离线草稿不自动迁入团队空间。
5. 检查“已同步 / 同步中 / 离线待传 / 冲突”状态。“刷新团队星轨”常驻显示，不必展开联网设置；立即同步仍保留在设置中。

### 在同一团队空间协作

登录后可在“团队数据空间”下拉框选择当前项目、分支下的共享空间；“刷新空间列表”用于发现其他实例新建的空间。空目录和读取失败分别提示，权限失败不视为空仓，也不会创建空间或回退到 master。

在左侧点击“+ 新建星轨”，新星轨立即选中，搜索和状态筛选自动清除。已有团队空间内的新增内容沿用自动同步；其他实例连接**同一 GitLab origin、项目、分支、空间**，即可通过“刷新团队星轨”或等待前台自动检查发现并选择它。搜索无结果时可一键清除筛选。

新空间仍须先在联网设置中填写合法空间标识、拉取核验，再确认首次写入；不会将旧离线草稿自动迁入。此处的空间目录来自已有 GitLab 数据布局，不是围炉成员自动发现，也不等于已经验证不同成员的 GitLab 权限。

凭据仅保留在本次会话内存。当前公开 SDK 未提供可用的安全持久化凭据接口，**关闭插件或重启后需要重新登录**。不使用普通宿主存储或团队文件保存令牌。切账号先退出，草稿不会串入另一账号。

默认要求 HTTPS；只有已明确授权的公司精确 origin 例外。该 HTTP 连接**未加密**，凭据与内容可能被读取或篡改；相似域、其它端口或其它 HTTP 地址不被放行。跨 origin 重定向不得携带鉴权；不修改代理、TLS、CSP 或宿主安全配置。公司 master 保持只读，不自动创建分支或修改权限。

## 已验证范围与限制

- 同一授权账号的两个独立真实桌面客户端已验证公司隔离空间的自动上传/拉取、冲突处理及请求中断恢复；**不同成员账号协作仍待上线验证**。
- 自动化夹具、真实 Chromium、本地服务及安装版 SDK 检查，与真实公司验证分别记录，不把 mock 叫作真实联测。
- 原生最小化生命周期及跨成员长时间稳定性尚未完整验收；不能宣称全场景长稳完成。异常可手动拉取/重新登录，先保留草稿。
- 本地草稿不是加密备份；仅将有权限在本机保存的业务内容写入空间。单次请求受宿主 1 MiB RPC 上限约束。
- 本地文件导入/导出仅用于备份兼容，不是团队联网同步。

## 开发与检查

需要 Node.js 22.12+，使用 npm ci、npm run check。检查包含类型、团队同步、网络/鉴权/重定向、活动记录、自动同步、布局、分支隔离、构建和验包。

可选宿主源码与已安装宿主测试通过环境变量配置，不内置开发者私有路径：

- STARMAP_HOST_ROOT：本地宿主源码目录。
- STARMAP_INSTALLED_HOST_ASAR：已安装宿主的公开程序归档。
- STARMAP_PLAYWRIGHT_PACKAGE：提供 Playwright 的 package.json 路径。
- STARMAP_BROWSER_PATH：可选已安装浏览器路径。
- npm run test:autosync-ui、npm run test:activity-ui：Chromium + 模拟宿主/数据，验证交互及不同尺寸几何。
- npm run test:shared-tracks、npm run test:shared-tracks-ui：共享空间选择、切换失败保留草稿、星轨发现、目录错误/空态及新建后可见性的定向代码/UI测试；不访问真实 GitLab，不代表不同成员联测通过。
- npm run test:desktop-integration：复制安装版代码到独立测试目录，使用独立 profile 与本地模拟服务，不访问生产团队数据。Windows 需要可运行的安装版宿主。

未配置的可选测试明确 skip；不代表已通过。发布资产为独立 HTML 插件压缩包，不附带任何本机凭据、缓存或业务数据。
