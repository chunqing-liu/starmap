# 星图 V5 设计决策

日期：2026-09-23  
适用端：`portal-desktop` Electron + React + Vite  
唯一需求基准：`pipeline/v5-requirements.md`

## 1. P0 根修

### 新建

V4 的「新建」实际上是带必填前置条件的表单：输入框为空时直接返回，因此用户只点击按钮会表现为无响应。V5 将名称改为可选；一次点击总会创建一条名为「新建任务」的星轨并立即选中、打开右侧星轨详情。任务名称可在详情中继续编辑。

### localStorage 脏数据

保留既有键 `beings:star-map:v4`，不另造迁移门禁。读取和写入共用同一套归一化：`customTransitions` 只接受具备 `fromNode`、`event`，并至少具备一个目标或目标状态的对象；null、数组内原始值和缺字段对象均被丢弃。`demandTransitions` 在进入 `buildEdges` 前再使用归一化结果，避免运行期旧对象绕过加载阶段。

### 「适配」字号

根因是 V4 工具条将所有按钮统一设为 14px，适合 `+/-` 图标却不适合文字按钮。「适配」增加独立类并固定为 10px 正文字号；专注按钮维持同一字号。

## 2. 闸口与推进规则

- 普通节点和闸口继续共用节点模型，`kind: gate` 表示必须人工审核。
- 闸口完成必须同时填写人工拍板人与完成证据。
- 节点准备开始、运行、完成或跳过前，会检查直接前置节点；若前置为未完成或缺少人工审核记录的闸口，则拒绝推进并说明阻塞闸口。
- 普通节点不增加强制人工确认，可按原有状态规则推进。
- 新建工具条、画布空白右键菜单和节点详情均提供闸口入口；锁定的流程节点不可改型。

## 3. 星轨标题、分组与筛选

星轨显示标题统一为「状态 · 任务名称」，组织/分组信息只作为副信息。左栏支持名称/摘要/经办人搜索、需求状态筛选，以及按流程分组或按状态分组。

星轨多选采用桌面列表惯例：单击单选，Ctrl/Cmd+单击增减选中项；右键菜单可将两条及以上星轨放入自定义分组，或删除选中星轨。为避免把整个星图清空，最后一条星轨不可删除。

## 4. 站尺寸自适应

站的展开高度不再固定为 420px，而是取「最小高度」与「站内最低节点底边 + 底部留白」的较大值。新增节点的初始纵坐标按站内节点数递增，避免所有新节点堆叠在同一点；拖入站的命中区域也使用动态高度。低倍缩放的站摘要仍保持 170px，避免全局鸟瞰图被少数大站拉高。

## 5. 右键菜单

- 左栏星轨：成组、删除。
- 画布节点/站：选中目标后右键删除；锁定站仍由删除函数拒绝含节点删除。
- 画布空白：新建普通节点、闸口、站。

认领和完成不放进右键菜单：两者需要负责人、证据、闸口校验等上下文，保留在右侧详情可避免误操作。

## 6. 两个默认流程组

V5 内置两个流程定义，并在星轨实例上用 `workflowId` 选择：

1. 「需求开发流程组」继续使用 Agent Team 的需求确认、评审、开发、测试、发布流程与 H1-H4 人工审核点。
2. 「bug 修复组」新增提报、修复、验证、关闭四站流程；星轨详情包含标题、P0-P3 优先级、经办人、详情、附件和状态。状态全集严格使用「开放 / 开发中 / 测试中 / 重新打开 / 已解决 / 已关闭」。每次变更状态必须填写改动内容，并写入 ISO 时间、目标状态和内容三项历史记录。

当前 Jira MCP 未配置，因此字段和流转只按负责人本轮口述建模，后续获得真实工单后再校准，不把现状描述冒充 Jira 最终契约。

## 7. 范围与验证

实现只修改 `desktop/renderer/pipeline/`，继续沿用 `v4.css` 作为该模块样式入口，避免无收益的文件改名。不改聊天主流程、Electron 主进程或只读参考仓；不启动 Electron。验证仅执行 `npx tsc --noEmit` 与 renderer Vite 生产构建，交互由负责人真机验收。
