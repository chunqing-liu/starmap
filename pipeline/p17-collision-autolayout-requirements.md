# P17 拖拽碰撞自动布局（2026-09-24 16:04 醇青反馈）

## 背景（用户原话）
> 顺便增加碰撞时自动布局，就是不允许两个节点重叠，如果把一个节点拖到到了另一个节点上，那根据相对重叠位置判断意图是想放在原节点上方还是下方，然后自动给它布局到合适的位置。这样随手拖动节点就容易自动放到符合意图的位置

## 需求语义
拖放一个节点结束时，如果它与其他节点（item 节点）发生视觉重叠，不允许重叠保持原样——根据两节点的相对位置推断用户意图，自动把被拖节点放置到不重叠的合适位置。

## 判定规则（拍板为默认实现，codex 可微调参数但语义不变）
1. **重叠判定**：两个 item 节点矩形（含少量容差，建议 8px）相交即算重叠。只对 item 节点生效；站容器（station）不参与碰撞（节点拖进站内本来就是合法落点）。
2. **意图推断**：被拖节点中心落在被撞节点中心的**上方**（y 更小）→ 放到它上方；下方 → 放到它下方。x 完全错开但 y 重叠的边缘情况：按 y 中心比较即可，规则保持简单。
3. **落位计算**：目标位置 = 被撞节点正上/正下方，垂直间距留 24px（与站内布局节奏一致），x 保持用户拖放的 x（不强行对齐，尊重用户的水平意图）。若该位置又与其他节点重叠，沿同方向继续找第一个不重叠位置（最多迭代 N 次，N=站内节点数）。
4. **触发时机**：onNodeDragStop（persistDraggedNodes 内，落点归属判定之后、写 positions 之前）。多选拖动时逐个处理。
5. **站内/站外都适用**：站内拖动（P15 场景）也要碰撞避让——站内节点重叠同样触发；拖出站的节点落点也避让。站容器边界不裁剪（节点可以拖出站 bounds，现状如此，不改）。

## 不做（本期边界）
- 不做「推挤」效应（其他节点让位）——只移动被拖节点。
- 不做连线避让/重排——只管节点矩形。
- 不改新建节点的默认落位（画布中央，已有逻辑）。

## 验收要点（隔离实例 9223，CDP）
1. 拖 N01 到 N03 正上方释放（中心 y < N03 中心 y）：N01 最终位置在 N03 上方、垂直间距 ≈24px、x 保持拖放 x、与所有节点无矩形相交（容差 8px）。
2. 拖到正下方释放：落在下方，同上断言。
3. 拖到密集区（多个节点叠着的目标位）：迭代避让后无任何重叠。
4. 拖到空白处：位置原样，不触发移动。
5. 站内拖动重叠：同样避让且不改变 nodeIds 顺序（P15 回归）。
6. 跨站拖动落点与目标站节点重叠：先按 P15 归属站，再在站内避让。
7. tsc --noEmit 通过。

## 实现提示
- persistDraggedNodes 已有 latestById（拖动后位置）；碰撞检测需要全量 item 节点的「当前渲染位置」——站内节点的渲染位置用 visibleNodePosition（page.tsx:143）换算，别直接用 positions 原值（会被站头 clamp）。
- 常量建议：COLLISION_TOLERANCE=8, VERTICAL_GAP=24，放 page.tsx 顶部常量区。
